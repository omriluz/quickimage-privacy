SyncLead: LinkedIn Profile Capture Privacy Policy

Last updated: September 29, 2026

What SyncLead handles

SyncLead handles only data needed for its user-requested workflow:

  • visible name, headline, current company, location, about text, and profile URL from the individual LinkedIn profile open when the user presses Capture visible profile;
  • a local list containing those captured fields and local created/updated timestamps;
  • an optional HTTPS webhook URL;
  • an optional Notion integration token, data source ID, and title property name.

SyncLead does not enrich profiles, discover emails or phone numbers, read messages, crawl profile lists, collect browsing history, use analytics, display advertising, or operate a publisher-owned server.

When data leaves the browser

Profile data leaves the browser only when the user presses Send to webhook or Send to Notion and grants Chrome access to the displayed destination host.

  • A webhook send goes directly from Chrome to the HTTPS URL configured by the user.
  • A Notion send goes directly from Chrome to https://api.notion.com/v1/pages with the locally stored integration token.

The selected destination's own privacy terms and retention practices apply after it receives the data. SyncLead refuses HTTP destinations and redirects, limits request duration to 12 seconds, and reads at most 64 KB of a destination response.

Local storage and retention

SyncLead stores up to 500 deduplicated leads and optional destination settings in chrome.storage.local. This storage is local to the Chrome profile and is removed when the extension is uninstalled. Users can delete all leads and destination settings separately from the extension.

Chrome extension storage is not encrypted. The extension sets storage access to TRUSTED_CONTEXTS, preventing injected page code from reading it through a content-script context. Device and browser-profile access remain security boundaries that users must protect.

Permissions

  • activeTab: temporary access to the active page after the user opens the extension, used for one requested capture.
  • scripting: injects the one-shot visible-profile extractor into that active tab.
  • storage: saves the lead list and optional destination settings locally.
  • optional https://*/* host access: requested for the exact configured webhook host or Notion host only when the user presses send. It is not granted at installation.

Sharing and sale

The extension publisher does not receive, sell, or use the handled data for advertising, credit decisions, or unrelated purposes. User-directed transfers to the user's configured webhook or Notion workspace are the only external disclosures performed by the extension.

Local and functional data use

SyncLead handles profile name, headline, company, location, about text and URL; local lead records, webhook settings and optional Notion integration token. Local-only processing is still disclosed as data handling. Existing site and service privacy terms apply to the functional requests or user-directed transfers described above.

Limited Use

Use of user data complies with the Chrome Web Store User Data Policy, including its Limited Use requirements. Data is used only to provide the extension's disclosed single purpose and its associated local controls and status. The publisher does not sell user data, use or transfer it for unrelated purposes or advertising, or use it to determine creditworthiness or for lending. External recipients, when any, are limited to the functional, user-directed workflows described in this policy. The publisher does not operate a service that receives these extension records.
