MockFlow: Local API Response Mocker Privacy Policy

MockFlow does not include analytics, advertising, telemetry, accounts, payments, or remote application services.

Data handled

The extension stores rule names, exact page origins, request URLs, redirect destinations, header changes, enabled state, and user-authored JSON response bodies in Chrome local extension storage. Stored rules remain on the device unless the user explicitly exports a rules file. Enabled redirects and header changes alter the page’s actual network requests: destinations receive those requests and configured headers. Avoid putting secrets in shared rule exports. Mock response content is provided to the opted-in webpage’s own JavaScript. Import reads only the file the user selects.

The page-world shim compares page fetch() and asynchronous XHR URLs with enabled rules. Matching calls receive the locally stored response. Unmatched calls continue through the browser normally. MockFlow does not log request bodies, response bodies, browsing history, or credentials.

Permissions

  • activeTab: lets the user activate response mocking on the page where they opened MockFlow.
  • scripting: installs the local fetch/XHR shim in that page's main JavaScript world.
  • declarativeNetRequest: applies the user's enabled redirect and header rules.
  • storage: saves rules locally.
  • Optional http://*/* and https://*/* host access: the manifest declares the categories Chrome requires. At save or enable time, MockFlow requests each needed scheme and hostname; Chrome's permission covers that host on all ports. MockFlow's own page-origin comparison remains exact, including the port, and DNR rules are limited to matching tab IDs. Denial leaves the previous rules active.

No data is sold, shared, or transmitted by the extension developer.

Local and functional data use

MockFlow handles rule names, origins, request/destination URLs, headers and user-authored mock bodies; these may contain authentication values or personal information entered by the user. Local-only processing is still disclosed as data handling. Existing site and service privacy terms apply to the functional requests or user-directed transfers described above.

Limited Use

Use of user data complies with the Chrome Web Store User Data Policy, including its Limited Use requirements. Data is used only to provide the extension's disclosed single purpose and its associated local controls and status. The publisher does not sell user data, use or transfer it for unrelated purposes or advertising, or use it to determine creditworthiness or for lending. External recipients, when any, are limited to the functional, user-directed workflows described in this policy. The publisher does not operate a service that receives these extension records.
