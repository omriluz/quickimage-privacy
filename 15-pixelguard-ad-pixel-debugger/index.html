PixelGuard — Ad Pixel Debugger Privacy Policy

Last updated: September 29, 2026

PixelGuard runs locally in Chrome. It does not operate a developer server, analytics service, account system or advertising tracker.

Data handled

Only after the user selects Start capture, PixelGuard observes supported ad/conversion pixel requests initiated by that authorized site in that tab. It derives a provider, event name, pixel/conversion ID, event or transaction ID, conversion label, HTTP method, provider endpoint path, and a small allowlist of commerce parameters such as value, currency, content ID, order quantity and order ID.

PixelGuard does not request or read cookies. It does not request request headers or response headers, so it does not collect cookie or authorization header values. It does not retain full request URLs, page URLs, full raw bodies, email/phone matching fields or arbitrary parameters. Retained field values are length-limited.

Storage and retention

Sanitized records are stored in chrome.storage.session for the current browser session. Capture is isolated by tab and site origin, with a maximum of 60 records per tab and at most 10 restored capture sessions. Same-origin navigation clears records. Cross-origin navigation, tab closure, permission revocation, Clear, or Stop capture removes applicable data. Closing the browser clears Chrome session storage.

Data is not sold, shared with the publisher or sent to a PixelGuard-controlled server. The ad pixel requests themselves are initiated by the tested website and directed to the named advertising providers; PixelGuard observes them locally and does not add or resend them.

Permissions

  • activeTab: identify the tab where the user opened PixelGuard.
  • webRequest: observe supported provider requests without blocking or modifying them.
  • storage: keep bounded session records across service-worker suspension.
  • Optional HTTP/HTTPS host access: requested on Start capture for the current site hostname and scheme plus supported provider endpoint origins. Chrome host permissions cover all ports on a hostname; PixelGuard separately gates capture to the exact authorized page origin, including its port. It is not granted at installation.

Removing site access in Chrome stops affected capture. Stop capture releases permissions that are not needed by another active tab session.

Limits

An observed request is not evidence of server receipt, acceptance, deduplication or conversion attribution. PixelGuard does not inspect provider accounts or server-side Conversion API traffic.

Local and functional data use

PixelGuard handles bounded provider/event/transaction identifiers, commerce values and request/session metadata; custom fields may contain personal information despite redaction. Local-only processing is still disclosed as data handling. Existing site and service privacy terms apply to the functional requests or user-directed transfers described above.

Limited Use

Use of user data complies with the Chrome Web Store User Data Policy, including its Limited Use requirements. Data is used only to provide the extension's disclosed single purpose and its associated local controls and status. The publisher does not sell user data, use or transfer it for unrelated purposes or advertising, or use it to determine creditworthiness or for lending. External recipients, when any, are limited to the functional, user-directed workflows described in this policy. The publisher does not operate a service that receives these extension records.
