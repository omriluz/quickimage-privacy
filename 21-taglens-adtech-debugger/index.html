TagLens — Analytics QA Debugger Privacy Policy

Last updated: September 29, 2026

TagLens runs locally in Chrome. It has no developer-operated server, telemetry, account system, or advertising tracker.

Data handled

Only after the user selects Start capture, TagLens observes supported GA4, Adobe Analytics, and GTM browser requests initiated by the authorized site in that tab. It derives a provider, event/request label, measurement/container/report-suite ID, method, endpoint path, diagnostics, and bounded decoded parameters.

TagLens does not request or read cookies. It does not request request headers or response headers, so it does not collect cookie or authorization header values. It does not retain full request URLs or raw request bodies. Before retention, likely identity/contact keys and email/phone-shaped values are replaced with [redacted], query strings are removed from URL-shaped values, known secret/header fields are omitted, and keys/values/counts are length-limited. Because custom analytics fields can contain arbitrary business data, heuristic redaction cannot identify every sensitive value; users should capture only authorized test sites and review exports before sharing.

Storage and retention

Sanitized records are stored in chrome.storage.session for the current browser session. Capture is isolated by tab and site origin, with at most 80 records per tab and 10 simultaneous sessions. Same-origin loading and Clear erase the feed and rotate its generation. Cross-origin navigation, unavailable tab URL access, tab closure, permission revocation, or Stop capture removes the applicable session. Closing Chrome clears session storage.

Data is not sold, shared with the publisher, or sent to a TagLens-controlled service. The analytics requests are initiated by the tested website and directed to the named providers; TagLens observes them locally and does not add or resend them.

Permissions

  • activeTab: identify the tab where the user opened TagLens.
  • webRequest: observe supported provider requests without blocking or modifying them.
  • storage: preserve bounded session records across service-worker suspension.
  • Optional HTTP/HTTPS host access: requested on Start capture for the exact current site and supported provider endpoint patterns. It is not granted at installation.

Limits

An observed request is not evidence of server receipt, acceptance, processing, reporting, attribution, GTM execution, or server-side tagging. TagLens does not inspect provider accounts.

Local and functional data use

TagLens handles bounded provider/event identifiers, request paths, parameters and session metadata; custom analytics fields may contain personal information despite heuristic redaction. Local-only processing is still disclosed as data handling. Existing site and service privacy terms apply to the functional requests or user-directed transfers described above.

Limited Use

Use of user data complies with the Chrome Web Store User Data Policy, including its Limited Use requirements. Data is used only to provide the extension's disclosed single purpose and its associated local controls and status. The publisher does not sell user data, use or transfer it for unrelated purposes or advertising, or use it to determine creditworthiness or for lending. External recipients, when any, are limited to the functional, user-directed workflows described in this policy. The publisher does not operate a service that receives these extension records.
